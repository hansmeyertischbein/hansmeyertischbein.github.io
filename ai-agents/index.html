How I work with AI agents

I use AI agents for work that repeats on a schedule: reading the news before the market opens, keeping analyses on this site up to date, and planning my day. This page shows what they do, how their work is checked, and where they have gone wrong.

One run, start to finish

Every agent follows the same pattern. A schedule starts it, it works from written instructions, and nothing reaches the site or me before it has passed the checks.

  1. 1TriggerA fixed time, or the day of a Norges Bank decision
  2. 2InstructionsA method file in the code repository, versioned like code
  3. 3ResearchWeb search and the original sources: Norges Bank, Statistics Norway, company reports
  4. 4ComputeNumbers go through scripts, not through the model's head
  5. 5ChecksSources linked, figures cross-checked, page tested on phone and desktop
  6. 6PublishCommit to GitHub, the site rebuilds
  7. 7ReportA short message to me with the result and the link, or exactly what failed

If a check fails, the run stops at step 5 and tells me why. Half-finished work is never published.

    How the output is checked

    RuleWhyExample
    Every number links to a source the agent openedA model can produce a plausible number from memory that is out of date or wrongEach market analysis ends with a numbered source list
    Never estimate and present it as factA gap is better than a made-up figureThe briefs write "n/a" for any price they could not confirm
    Fetch data twice, in two forms, and compareData read through a language model can be garbled without any error messageInflation is fetched as an index and as a 12-month rate; they must agree within 0.2 points
    Calculate in codeScripts give the same answer every time and can be checkedThe Taylor rule, output gap and project feed are built by Python scripts with built-in assertions
    Look at the resultA page can be correct and still broken on a phoneEvery page is opened at 390 and 1,100 pixels wide before publishing
    Read-only unless told otherwiseActions that affect other people need a human decisionThe digest drafts replies; it sends nothing until I answer "gjør 3"
    Fail loudlyA silent failure is worse than a failed runEvery run ends with a message, including what went wrong

    Where it went wrong, and what changed

    A shifted inflation series

    When building the Taylor rule page, the first fetch of Statistics Norway's inflation data came back with 142 values for 144 months. The summary filled them in order, which moved every figure in the later years by two months. Nothing looked obviously wrong.

    Fix: fetch the data with one labelled value per line, fetch the index as well, and let the build script reject any month where the two disagree.

    Formulas printed as code

    The PDF behind the prioritisation tool showed several formulas as raw LaTeX in grey boxes instead of typeset maths. The text was right, but a reader could not use it.

    Fix: the formulas were typeset and the PDF replaced. Generated documents are now opened and looked at, not only built.

    A tool that looked finished but was not

    The first version of the CV generator rendered a nice page but did not produce a usable file, and its example used my own CV.

    Fix: rebuilt on the method behind my real CV, tested by downloading and opening the files, with a fictional example person.

    Pages that scrolled sideways on a phone

    Several pages were fine on a laptop and overflowed on a phone: a grid that would not shrink, a chart marker outside its track, buttons that wrapped badly.

    Fix: every publish now checks the page width at 390 pixels and looks at screenshots before it goes live.

    What I have learned about instructing agents

    • Write the method down, outside the prompt. A method file in the repository can be read, improved and versioned. The scheduled prompt just says "follow the method".
    • Say what good looks like. Sections, tone, units, which sources to prefer, and what not to do.
    • Separate judgement from arithmetic. Let the model research, explain and judge; let code compute.
    • Make failure an expected outcome. Tell the agent exactly what to do when a source is missing or a check fails.
    • Keep a human on decisions that affect others. Agents prepare; I approve.
